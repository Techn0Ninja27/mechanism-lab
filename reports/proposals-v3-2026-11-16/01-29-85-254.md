# Conflict-Conditioned Forced-Choice Auditing of Unlearned Code Canaries, Scored by an Execution Oracle

**Status:** an evaluation-protocol hypothesis, not an erasure method. The seed atoms are unranked and I make no novelty claim.

## 1. Hypothesis

In a small code LM that learned synthetic API canaries and was then unlearned with a standard method, the execution-scored preference for the forgotten specification over an exchangeable counterfactual, when both appear as conflicting in-context documents, separates forgotten items from never-seen items better than direct recall. It also adds held-out predictive value beyond recall, loss-based membership inference and a vocabulary-projection trace probe, while staying at chance in a retrain-without-canaries reference.

## 3. Interface declaration (all bridges are my conjectures)

- **Bridge A (29×85).** If unlearning suppresses recall but leaves residue, the confirmation bias reported by Xie et al. should tilt the model toward the forgotten spec when it conflicts with a counterfactual. The quantity measured is recognition, not recall.
- **Bridge B (254 as instrument).** The model writes a reimplementation, and execution on discriminating inputs classifies it as true spec, counterfactual, or neither. This needs no LLM judge and is robust to surface form. It scores behaviour and verifies nothing about weights.
- **Bridge C (254 as loop, on probation).** Pass/fail-only repair feedback is a bounded-information cue. Faster convergence on forgotten than on never-seen items would indicate "savings".
- **Partial REJECT.** I see no causal interface by which closed-loop debugging improves erasure, and I do not propose one. If Bridge C fails ablation A3 below, atom 254 reduces to a scorer and the three-way conjunction should be treated as a two-atom idea plus a metric.

## 4. Intervention and outcome

- **Intervention:** the evaluation prompt condition. It is either a direct recall prompt or a counterbalanced two-document conflict prompt, with an optional binary-feedback repair round.
- **Outcome:** item-level AUROC for distinguishing trained-then-unlearned from never-trained canaries. Ground truth is known by construction.

For item *i*, over prompt variants Π (document order × held-out template × samples), with generated reimplementation *g*:

s_i = (1/|Π|) Σ_π [ 1{exec(g_π) ≡ spec_true,i} − 1{exec(g_π) ≡ spec_cf,i} ]

The score direction is fixed on the dev split. Over-suppression, meaning systematic avoidance of the true spec, is reported separately.

## 5. Closest supplied prior art and proposed difference

- **Component:** ConceptVectors (trace versus masking) and [SalUn](https://proceedings.iclr.cc/paper_files/paper/2024/file/ec4d2e436794d1bf55ca83f5ebb31887-Paper-Conference.pdf) (saliency unlearning). These are used here as a baseline probe and a method under audit.
- **Pairwise:** [Rich Knowledge Sources Bring Complex Knowledge Conflicts](https://aclanthology.org/2022.emnlp-main.146.pdf) and Xie et al. construct parametric-versus-context conflicts, but not as a post-unlearning audit, as far as the supplied notes show.
- **Strongest competitor:** FIUBench-style membership inference and adversarial privacy attacks, plus the edit-as-unlearning comparison space ([Editing as Unlearning](https://ojs.aaai.org/index.php/AAAI/article/view/41097)).
- **Proposed difference:** a two-alternative conflict probe with exchangeable counterfactuals, an execution scorer and a retrain reference, tested for incremental value over those baselines. I am uncertain whether this already exists under other terminology (recognition tests, relearning savings). The review is bounded, not exhaustive.

## 6. Compatibility assumptions

- Canaries are synthetic and so absent from pretraining. Retraining the fine-tune stage without them is then an exact reference for that stage only.
- True and counterfactual specs are drawn i.i.d. from the same generator, so without residue neither is preferred.
- Function names are random syllable strings. One source unit warns that in-vocabulary tokens such as digits carry prior meaning that interferes with arbitrary associations. Names with above-threshold base-model spec preference are filtered before the splits are drawn.
- Unlearned models still produce runnable code. The "neither" rate is reported, and a high value makes the run inconclusive.

## 7. Phase-zero falsification experiment

**Data.** `synthlib` has 600 pure-Python functions. Each behaviour composes two of eight primitive operations with small integer parameters. Each function has one doc string and 20 templated usage examples. Functions are randomly assigned to 200 forget, 200 retain and 200 never-seen (excluded from all training). Everything is benign and synthetic, with no real private data.

**Models.** One open LM of about 1.5B parameters or fewer (for example the Phi-1.5 scale used in LoKU), with 3 seeds. The conditions are:
- M0: fine-tuned on forget + retain. This is the positive control.
- M-ref: fine-tuned on retain only. This is the retrain reference and negative control.
- M-GA, M-LoKU, M-SalUn: M0 unlearned on the forget set, with identical step budgets and a retain-utility floor (retain pass rate at least 90% of M0).

**Held-out scheme.**
- Evaluation templates are disjoint from training templates.
- Functions are split 50/50 into dev (direction and classifier fitting) and test.
- Prompts, counterfactuals and discriminating inputs are generated by script and frozen before any model is evaluated.
- Scoring is sandboxed execution only.

**Baselines (same generation budget per item).**
- B1: direct recall pass rate.
- B2: loss-based membership score on held-out usage text.
- B3: vocabulary-projection trace score, ConceptVectors-style.

**Controls and ablations.**
- A1: single-document prompts, true-only and counterfactual-only. These separate copying ability from conflict-specific preference.
- A2: string-match scorer instead of execution. This tests whether the execution oracle matters.
- A3: no documents, with up to 3 repair rounds of pass/fail-only feedback. This tests Bridge C.
- Randomised control: permuted forget/never-seen labels.

**Metric.** Test-split AUROC (forget versus never-seen) per model, with bootstrap 95% CIs over items and seeds. Incremental value is ΔAUROC of logistic regression on {B1, B2, B3, s} versus {B1, B2, B3}.

**Proposed preregistered rule.**
- *Validity gate:* M0 AUROC(s) ≥ 0.80. Otherwise the probe is insensitive and the run is inconclusive rather than a falsification.
- *Pass* requires all three:
  1. In at least 2 of 3 unlearned models, AUROC(s) ≥ 0.65 with lower CI bound > 0.55.
  2. The M-ref CI for AUROC(s) contains 0.50.
  3. ΔAUROC ≥ 0.05 with paired-bootstrap CI excluding 0 in at least 2 of 3 unlearned models.
- *Fail:* any of the three is violated. If only (3) fails, the probe is redundant with existing tests.
- *Atom-254 rule:* if A3 adds less than 0.02 AUROC over s, drop the feedback loop. If A2 matches execution scoring within 0.02, the execution atom contributes nothing here.

## 8. Compute (estimate)

Assumptions: one 24 GB GPU, sequences of about 150 tokens, and LoRA or full fine-tuning of a model of 1.5B parameters or fewer.

| Item | Estimate |
|---|---|
| Training: 15 runs (3 seeds × 5 conditions) at ≤1 GPU-hour each | ≤15 GPU-hours |
| Generation: about 150k short completions | 5–10 GPU-hours |
| Trace probes and sandboxed CPU execution | under 5 hours |
| **Total** | **roughly 25–40 GPU-hours** |

This estimate is unmeasured.

## 9. Strongest objection and failure cases

- **Strongest objection:** the probe may be membership inference in disguise. Preference for a previously seen string can reflect token-level familiarity that B2 already captures. Criterion (3) exists to test this, and a null there is a clean kill.
- **Recognition is not usable knowledge.** A positive result shows non-equivalence to retraining on this probe. It does not show the content is extractable, and a null does not certify erasure. Probes are lower bounds.
- **Transfer risk.** Xie et al.'s confirmation bias was reported for natural-language evidence. It may be absent in small code models, which the validity gate would catch.
- **Degenerate models.** Aggressive unlearning may produce "neither" outputs or blanket avoidance, mimicking or hiding signal.
- **External validity.** Synthetic canaries learned in one fine-tuning stage may not resemble diffuse pretraining knowledge. The exact-retrain reference is unavailable there.
- **No adaptive attacker.** Phase zero omits relearning and optimised attacks. Those are required before any claim about robustness.

## 10. Decision: INVESTIGATE phase zero only, and REVISE the conjunction

- **Why investigate:** Bridge A is a plausible, source-motivated and cheaply falsifiable interface between unlearning audits and knowledge-conflict behaviour, with ground truth by construction and a retrain reference.
- **Why revise:** the execution atom is currently justified only as a deterministic scorer. Its closed-loop role is unproven and is rejected by default unless A3 clears its threshold.
- **What would change the verdict:** failing criterion (3) reclassifies the idea as covered by existing MIA and trace tests. Passing all three criteria alongside a positive A3 would justify a second phase with adaptive relearning attacks and a larger model.
